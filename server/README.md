# SurakshaX API (`server/`)

Backend for the SurakshaX Android app: FastAPI + SQLAlchemy, Postgres in production (SQLite locally).

## Run locally

```bash
cd server
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env          # optional: fill in ADMIN_PASSWORD etc.
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

- API docs: http://localhost:8000/docs
- Tests: `python -m pytest -q`
- Phone on the same Wi-Fi: in the app, Settings → Server, enter `http://<your-PC-IP>:8000`.
- Windows: if `pip install` fails with a long-path error (Twilio), create the venv in a short path such as `C:\sxv`.

## Deploy on Render

`render.yaml` at the repo root creates the web service **and** a Postgres database.

1. Push the repo to GitHub.
2. Render → **New → Blueprint** → pick the repo.
3. Fill in the values it asks for: `ADMIN_PASSWORD`, `PUBLIC_BASE_URL` (the service URL, e.g. `https://surakshax-api.onrender.com`), `OSM_USER_AGENT` (`SurakshaX/3.0 (contact: your@email)`), and the Twilio values if you use Twilio.
4. Wait for the deploy, then open `https://<service>.onrender.com/health`. It should show `"database": "ok"`.
5. If the URL isn't `https://surakshax-api.onrender.com`, build the APK with `EXPO_PUBLIC_API_URL=<your URL>`.

`JWT_SECRET` is generated by Render. `DATABASE_URL` is wired from the database automatically.

Free-plan limits: the web service sleeps after 15 min idle (30–50 s cold start), and Render's free Postgres expires after 30 days. Use a paid instance and database before real users depend on it.

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | Production | Postgres URL (`postgres://…` is accepted). Empty → local SQLite file |
| `JWT_SECRET` | Production | Signs login tokens; changing it logs everyone out |
| `ADMIN_PASSWORD` | For dashboard | Password for `/police_dashboard` (user `ADMIN_USERNAME`, default `admin`) |
| `PUBLIC_BASE_URL` | Recommended | Base for tracking links sent in SMS |
| `OSM_USER_AGENT` | Recommended | Identifies the app to OpenStreetMap services |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER` | Optional | Server-side SOS SMS + voice call |
| `CORS_ORIGINS` | Optional | Allowed browser origins (default `*`) |
| `SOS_MAX_PER_WINDOW`, `SOS_WINDOW_MINUTES` | Optional | Twilio sends allowed per user (default 5 per 10 min) |
| `TRACKING_TTL_HOURS` | Optional | How long a live-location link stays active (default 2) |

## Endpoints

| Method | Path | Auth | |
|---|---|---|---|
| GET | `/health` | – | Status, database check |
| POST | `/api/register`, `/api/login` | – | Returns `{success, token, user}` |
| GET / PUT | `/api/user/profile` | Bearer | Read / update profile |
| POST | `/api/user/guardians` | Bearer | Replace emergency contacts |
| DELETE | `/api/user` | Bearer | Delete account and its data |
| GET | `/api/incidents` | Bearer | The user's own SOS history |
| POST | `/emergency_dispatch` | Bearer | Record SOS, nearest police, Twilio (rate-limited) |
| POST | `/tracking/update` | Bearer | Push a location to a tracking session the user owns |
| POST | `/tracking/{id}/stop` | Bearer | End sharing |
| GET | `/tracking/{id}`, `/track/{id}` | Link | Live location JSON / map page for guardians |
| POST | `/predict_risk` · GET `/hotspots` | – | Area risk |
| POST | `/safe_route` · GET `/geocode` | – | Routing and address search (OpenStreetMap) |
| POST | `/police/nearest` | – | Nearest stations (bundled OSM dataset, all India) |
| POST | `/voice_sos` | – | Distress-word detection (audio upload or text) |
| POST | `/analyze_status` | – | Sensor-reading check |
| GET | `/police_dashboard`, `/admin/incidents` | Admin | SOS alerts for responders |

## Layout

```
server/
  app/
    main.py        app setup, error format, /health
    config.py      environment variables
    db.py models.py  database + tables (users, guardians, tracking_sessions, location_points, incidents)
    security.py    password hashing, login tokens, admin check
    pages.py       live-tracking page, admin dashboard
    routers/       auth, safety, sos, admin
    services/      geo (OpenStreetMap), risk model, routing, voice model, Twilio
  models/          voice_cnn.onnx, crime_rf_model.joblib
  data/            india_police_stations.json, india_area_grid.npz (lamps + shops per ~100 m cell)
  scripts/         build_area_grid.py (rebuilds the grid from an OpenStreetMap extract)
  tests/
```

### Map data for risk scores

Area risk and safe routes read street-lamp and shop/amenity counts from `data/india_area_grid.npz` (0.7 MB, bundled), so they're instant and don't depend on the public Overpass servers, which are often overloaded. Overpass is only used if that file is missing. To refresh it with newer OpenStreetMap data (a few times a year is plenty):

```bash
pip install osmium
# download https://download.geofabrik.de/asia/india-latest.osm.pbf (~1.7 GB), then:
python scripts/build_area_grid.py path/to/india-latest.osm.pbf
```

The current file was built from the Geofabrik India extract of 20 Oct 2026 (29,288 street lamps, 485,667 shops/amenities). Data © OpenStreetMap contributors, ODbL.

Tables are created automatically on startup. For future schema changes, add Alembic migrations.

The map, risk and voice models were carried over from the old `backend/` (training scripts are still in `backend/ml/`).
